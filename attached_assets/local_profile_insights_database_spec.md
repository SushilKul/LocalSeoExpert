## Tables

### user_profiles
**Description:** Lightweight application-level user record linked to `auth.users` for product visibility and audit attribution in `LocalSEOExpert`.

**Columns:**
- `id: int4 NOT NULL DEFAULT GENERATED BY DEFAULT AS IDENTITY — primary key`
- `auth_user_id: uuid NOT NULL — FK to auth.users(id) for identity linkage only`
- `display_name: text NOT NULL — user-facing name for shared workspace attribution`
- `created_at: timestamptz NOT NULL DEFAULT NOW() — profile creation timestamp`
- `updated_at: timestamptz NOT NULL DEFAULT NOW() — last profile update timestamp`

**Constraints:**
- `PRIMARY KEY (id)`
- `UNIQUE (auth_user_id)`

**Indexes:**
- `UNIQUE INDEX on (auth_user_id) USING BTREE — one application profile per authenticated user`

**Business Rules:**
Shared-location access, role assignment, and content attribution are modeled in application tables rather than in `auth.users`.

**Associations:**
- `user_profiles belongs_to auth.users ON DELETE CASCADE`
- `user_profiles has many location_memberships`
- `user_profiles has many posts through post_events`

### locations
**Description:** Shared business locations that act as the required context for review and post workflows.

**Columns:**
- `id: int4 NOT NULL DEFAULT GENERATED BY DEFAULT AS IDENTITY — primary key`
- `external_ref: text nullable — stable mock/GBP-style identifier reserved for future adapter mapping`
- `name: text NOT NULL — location name shown in list and detail context`
- `address: text NOT NULL — display address for the shared location`
- `created_at: timestamptz NOT NULL DEFAULT NOW() — location creation timestamp`
- `updated_at: timestamptz NOT NULL DEFAULT NOW() — last location update timestamp`

**Constraints:**
- `PRIMARY KEY (id)`
- `UNIQUE (external_ref)`

**Indexes:**
- `INDEX on (created_at) USING BTREE — supports default location list ordering`
- `UNIQUE INDEX on (external_ref) USING BTREE — stable external lookup when present`

**Business Rules:**
A location must exist before reviews or posts can be managed. `external_ref` supports future integration mapping while current-version behavior stays mocked. -- forward-compat: §8 Next Mocked Location Profile Management

**Associations:**
- `locations has many location_memberships`
- `locations has many reviews`
- `locations has many posts`

### location_memberships
**Description:** Shared access mapping between users and locations, including the required collaborative role values.

**Columns:**
- `id: int4 NOT NULL DEFAULT GENERATED BY DEFAULT AS IDENTITY — primary key`
- `location_id: int4 NOT NULL — FK to locations(id)`
- `user_profile_id: int4 NOT NULL — FK to user_profiles(id)`
- `role: text NOT NULL DEFAULT owner — shared role value, CHECK (owner,mambers)`
- `created_at: timestamptz NOT NULL DEFAULT NOW() — membership creation timestamp`
- `updated_at: timestamptz NOT NULL DEFAULT NOW() — last membership update timestamp`

**Constraints:**
- `PRIMARY KEY (id)`
- `UNIQUE (location_id, user_profile_id)`
- `CHECK (role IN ('owner','mambers'))`

**Indexes:**
- `INDEX on (location_id) USING BTREE — FK join performance and location access checks`
- `INDEX on (user_profile_id) USING BTREE — FK join performance and user location list queries`
- `INDEX on (role) USING BTREE — role-based filtering within shared locations`
- `UNIQUE INDEX on (location_id, user_profile_id) USING BTREE — one membership row per user-location pair`

**Business Rules:**
Only assigned users can see or enter a location. The exact shared role values are `owner` and `mambers`.

**Associations:**
- `location_memberships belongs_to locations ON DELETE CASCADE`
- `location_memberships belongs_to user_profiles ON DELETE CASCADE`

### reviews
**Description:** Persisted mocked GBP-style customer reviews stored per shared location for paginated review handling.

**Columns:**
- `id: int4 NOT NULL DEFAULT GENERATED BY DEFAULT AS IDENTITY — primary key`
- `location_id: int4 NOT NULL — FK to locations(id)`
- `external_ref: text nullable — stable mock/GBP-style review identifier reserved for future adapter mapping`
- `reviewer_name: text NOT NULL — customer reviewer name displayed in the UI`
- `rating: int4 NOT NULL — numeric rating value for the review`
- `comment: text NOT NULL — customer review text`
- `reply_status: text NOT NULL DEFAULT no_reply — CHECK (no_reply,replied)`
- `reply_content: text nullable — saved business reply content, NULL means no reply yet`
- `replied_at: timestamptz nullable — timestamp of the latest saved reply`
- `created_at: timestamptz NOT NULL DEFAULT NOW() — review record creation timestamp`
- `updated_at: timestamptz NOT NULL DEFAULT NOW() — last review update timestamp`

**Constraints:**
- `PRIMARY KEY (id)`
- `UNIQUE (external_ref)`
- `CHECK (rating >= 1 AND rating <= 5)`
- `CHECK (reply_status IN ('no_reply','replied'))`
- `CHECK ((reply_status = 'no_reply' AND reply_content IS NULL AND replied_at IS NULL) OR (reply_status = 'replied' AND reply_content IS NOT NULL AND replied_at IS NOT NULL))`

**Indexes:**
- `INDEX on (location_id) USING BTREE — FK join performance and location review queries`
- `INDEX on (location_id, created_at) USING BTREE — paginated review list within selected location`
- `INDEX on (reply_status) USING BTREE — reply-status filtering`
- `UNIQUE INDEX on (external_ref) USING BTREE — stable external lookup when present`

**Business Rules:**
`Google Business Profile API is not integrated in the MVP. All GBP-related APIs should return simulated/mock data.` Reviews are read-only except for the ability to add or update reply content. A reply is attached to one review only.

**Associations:**
- `reviews belongs_to locations ON DELETE CASCADE`

### posts
**Description:** Persisted mocked GBP-style location posts that users can list, create, edit, and delete within a selected shared location.

**Columns:**
- `id: int4 NOT NULL DEFAULT GENERATED BY DEFAULT AS IDENTITY — primary key`
- `location_id: int4 NOT NULL — FK to locations(id)`
- `external_ref: text nullable — stable mock/GBP-style post identifier reserved for future adapter mapping`
- `summary: text NOT NULL — required post summary`
- `cta: text NOT NULL — required CTA label/value for the post`
- `post_type: text NOT NULL — required post type`
- `media_url: text nullable — optional media URL`
- `created_by_user_profile_id: int4 nullable — FK to user_profiles(id) for audit attribution of the latest creator`
- `updated_by_user_profile_id: int4 nullable — FK to user_profiles(id) for audit attribution of the latest editor`
- `created_at: timestamptz NOT NULL DEFAULT NOW() — post creation timestamp`
- `updated_at: timestamptz NOT NULL DEFAULT NOW() — last post update timestamp`

**Constraints:**
- `PRIMARY KEY (id)`
- `UNIQUE (external_ref)`
- `CHECK (length(btrim(summary)) > 0)`
- `CHECK (length(btrim(cta)) > 0)`
- `CHECK (length(btrim(post_type)) > 0)`

**Indexes:**
- `INDEX on (location_id) USING BTREE — FK join performance and location post queries`
- `INDEX on (created_by_user_profile_id) USING BTREE — FK join performance for attribution queries`
- `INDEX on (updated_by_user_profile_id) USING BTREE — FK join performance for attribution queries`
- `INDEX on (location_id, updated_at) USING BTREE — location-scoped post list ordering`
- `INDEX on (post_type) USING BTREE — post-type filtering`
- `UNIQUE INDEX on (external_ref) USING BTREE — stable external lookup when present`

**Business Rules:**
`Google Business Profile API is not integrated in the MVP. All GBP-related APIs should return simulated/mock data.` Each post belongs to exactly one location. `The backend should be designed so that adding GBP OAuth and real API integration later is straightforward.`

**Associations:**
- `posts belongs_to locations ON DELETE CASCADE`
- `posts belongs_to user_profiles ON DELETE SET NULL` via `created_by_user_profile_id`
- `posts belongs_to user_profiles ON DELETE SET NULL` via `updated_by_user_profile_id`

## Table Creation Order
1. `user_profiles` (depends on: auth.users)
2. `locations` (no application-table dependencies)
3. `location_memberships` (depends on: locations, user_profiles)
4. `reviews` (depends on: locations)
5. `posts` (depends on: locations, user_profiles)
